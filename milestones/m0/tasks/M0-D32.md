# M0-D32 — rung_record.py's handoff fallback reads the quoted model= level=

Box: win-laptop (Laser2025-20), Windows 11 Pro 26300, `py -3.12` (3.12.10). Rung: `rung_record.py now` →
`model=claude-opus-5-5 level=high plugin=installed` (the heading's Opus 5.5, high — no MISMATCH). Log: logs/M0-D32.log.

## Confirmed cause
`build()`'s fallback for a block with no session file ran `RUNG_RE` over the `- Handoff` line and took its first
`<Model> <n>, <level>` string; the quoted `model=<id> level=<level>` (the switch's form, PLAYBOOK §B.3) was never parsed.
So a quote with prose naming another rung first read that rung (M0-TJ3, V2, TM2, TM3, TM4, TM5, TR1 — M0-TM5's 5 of 6 by
prose, confirmed), and a quote with no prose rung read `unknown`.

## What changed (tools/pb/rung_record.py, +68 lines)
- `QUOTE_RE`; `handoff_rung(text)` → (rung, how): the `- Handoff:` field (its line and the indented lines under it), the
  quote first via `rung_name` (a dated id loses its date), else the first line's prose rung as before, else `unknown`.
- A no-session row's `rung_basis` now names the source: `no session; rung from the handoff's quote (model= level=)` · `…
  the handoff's prose` · `… nothing: the handoff names none`. `via` stays `handoff`; the counts line is unchanged.
- Selftest: `HANDOFF_PLAN` (five blocks), one check, one plant (`_prose_first`, the old reading) — 72 checks, 30/30 red.
- The local diff for a future annex swap: tasks/toolkit_local_diff.md item 6.
