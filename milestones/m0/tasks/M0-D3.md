# M0-D3 — content_gate.py's selftest stops on a Windows file lock (2026-10-08, win-laptop)

## Cause (measured — two causes, neither a held file handle)
1. **WinError 32 on `…\plain`**: the selftest's last check runs with `os.chdir(plain)`, inside the
   `TemporaryDirectory`; `os.chdir(home)` sat only in `finally`, after the `with` had exited, so the cleanup tried to
   remove the process's own working folder — Windows refuses (POSIX allows it). The crash is reported as the 37th
   "check" («selftest stopped after 36 checks»).
2. **«no --denylist → the list beside the tool» FAIL**: not the lock. The child process's stdout is text mode, so on
   Windows its lines end `\r\n`; the check looks for `"doc.md:<n>: zorblax_widget\n"` and never finds it. Measured:
   the child's raw stdout ends `b'...: quuxcorp\r\n=== NO-GO: 1 hit(s) ===\r\n'`. The tool's default list
   (`TOOL_DIR`) was right all along.
3. The «LF will be replaced by CRLF» warnings: `core.autocrlf=true` in `C:/Program Files/Git/etc/gitconfig` (the
   system level), seen by the selftest's temp repo.

## Fix (selftest only — the tool's behaviour unchanged), three edits
- `child()` returns its stdout with `\r\n` → `\n` (the check still needs exit 1 and the line).
- `os.chdir(home)` as the `with` block's last line, before the cleanup.
- the temp repo's `git add` runs with `-c core.autocrlf=false` (the lead's yes) — no check reads it.

Where it landed — the lead's answer (question tool, 2026-10-08): «Both, identical». `tools/pb/content_gate.py` and
PLAYBOOK.md annex §A's `#### tools/pb/content_gate.py` block, byte-identical (LF, compared as bytes: identical);
the `<!-- pb:file ... md5: -->` marker `90a1a464e16f` → `993166b08d43`. No other file carried the old md5.
