# M0-T127b — the display controls (detail)

Box: linux-pc (laserax-ai). Model claude-sonnet-5-5, level high (rung_record at launch). No GPU run: the scope is CPU-only.

## What changed
- `crates/sr-app/src/ui/display.rs` (new, `mod display_tests`, 11 cases): the view model. State is the engine's `Display`; `panel(view, &Display)`
  (none for Element), `show` (§4.12 value text), `parse_number`/`parse` (typed value → log₁₀ position, clamped), `command(control, x)`, and
  `apply(&mut Display, view, cmd) -> bool` — true only when a setting changed. Ranges are log₁₀ everywhere; S travels in kelvins snapped to
  9 significant digits (3,000 K stays 3000.0, so the default look is byte for byte; `dimming` tests `s <= 3000`).
- `desktop.rs`: `Sim.display` (apart from `Views`/`Tools`/world), `Sim::display_command` (Fit → `Renderer::fit_range` → `SetRange`; `set_display`
  only when `apply` says changed), `draw_left_panel` draws the active view's controls (Slider + DragValue with custom formatter/parser, Fit, Reset).
- `strings.rs` + contract §4.1 block: `views.glow_white`, `range_from`, `range_to`, `fit`, `reset`, after `views.density`, same order.
- `tools/pb/verify.json`: scope `ui_display` (expected 11); plant `tests/plants/display-reset-wrong.patch`; testing.md row; architecture.md bullets.

## Declared readings (cheap to reverse)
- «From ≥ 0.1 decade under To»: the end being moved stops at the other (the other never moves); values snapped to a 10⁻⁹ grid, so the gap is
  0.1 within 10⁻⁹ (tests compare with that tolerance).
- Grouping: "," only as a thousands group (first group 1–3 digits, the rest exactly 3) — "1,5", "12,34", ",500" are junk, never 15 or 1.5.
- "K" is accepted for Glow and Heat, not for Density (a Σ is no temperature). Past the float range ("1e9999") is the top of the span; an
  exponent longer than 4 digits is junk.
- The typed value is egui's `DragValue` (speed 0: click to type, never drags); Glow's value text is `format::temperature` ("10.0 K", 3 digits).
- Fit on the web build: `Renderer::fit_range` blocks on a read-back; wasm cannot wait, so `Sim::fit` returns None there and the click leaves the
  range as it is (not filed as a D: no native defect, a limit of the 127a query). Owed if the lead wants it on the web: an async fit.
