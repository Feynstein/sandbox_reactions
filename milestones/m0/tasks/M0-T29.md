# M0-T29 — gravity on the CPU twin (detail)

- API (`sr_physics::reference::grav`): `kernel(g, dx, dy)` (K(0, 0) = −g·`SELF_CELL`, `SELF_CELL` = 4 ln(1 + √2) =
  3.525494348…) · `source(sigma, sigma_vac)` (Σ where Σ ≥ Σ_vac, else 0) · `acceleration(phi, w, h)` (central
  differences, one-sided on the box's outermost ring, y down) · `Gravity::new(g)` / `.potential(sigma_src, w, h)` /
  `.field(sigma, sigma_vac, w, h)` → `Field { phi, gx, gy }`. Sinks (§1.4.3) are not in this task.
- G-GRAV1 measured first (the Deliver's fork): the central-difference force over every cell 0 < r ≤ 0.75a — a = 40:
  0.30 % (2820 cells, worst at (24, 30) of a 97² box); a = 20: 0.58 %; ratio 1.93; a = 40 centred on a cell corner
  0.31 %. Under 2 % by a factor of 6, so **no direct force kernels for M0-T31**: φ by one forward FFT, one multiply, one
  inverse, then the central differences.
- G-GRAV2: |Σ m·g| / Σ m|g| = 4e-16 on asym_blob (mass 1025.6), 2e-16 on a seeded scatter. Exact by construction while
  no mass sits on the box's outermost ring (the one-sided differences there break the antisymmetry) — the box margin
  (§1.3.3) guarantees it; M0-T31's shader must keep the same rim rule or the margin.
- Tests: tests/gpu/grav.rs, modules `grav::force` (4) and `grav::selfforce` (2); no adapter (the shader cases join at
  M0-T31). Scopes `grav_force`, `grav_selfforce` (R17: `_`). Plants: grav-kernel-exponent (powf(1.15) on r → 4 red),
  grav-kernel-shift (kernel(dx − 1, dy) → 2 red).
- Scene: scenes/asym_blob.json (128 × 128; disk + off-centre rect, both `t` 2.0, H only).
