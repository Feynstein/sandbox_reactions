# M0-D220 — a run's commands end with the run, however it ends (model=claude-opus-5-5 level=high, `rung_record.py now`)

Box: linux-pc (`laserax-ai`), RTX 5090, Python 3.12.3. Every run below on that box; raw output in logs/M0-D220.log.

## Cause (measured)
- tools/pb/verify.py's `run_command` starts each command with `new_group()` → `start_new_session=True` on POSIX, so the
  command, its `cargo test` and its `gpu-…` binary sit in a session of their own. `timeout`'s TERM (or KILL) reaches
  verify.py only; Python's default TERM ends it at once, nothing stops the groups, and they run on under PID 1 writing
  into `<log>.<pid>.<n>.part`. Reproduced on the old code with a `sleep 300` fixture: `timeout 3 verify.py sl` → exit 124,
  `bash -c 'sleep 300…'` alive under PPID 1, the part file left.
- INT (Ctrl-C) on the old code: raised in the main thread while the pool waited on commands Ctrl-C never reaches (their own
  sessions) — read from the code, not run.
- Who deleted M0-D219's part files is not verify.py: no code path unlinks a part file but its own run's after the join
  (`run_command`) and a red-arm's arm part (`redarm`). A hand clean-up while the writers lived is the reading.

## The pick and why (Deliver 1)
A guard process per verify.py process, in its own session, holding the run's groups on a pipe; at the pipe's end (any end
of verify.py, KILL included) or at `!` it SIGINTs each group still held, waits 4 s, SIGKILLs, notes the stop in the log.
Not PR_SET_PDEATHSIG (Linux only; reaches bash, not cargo or the gpu binary; fires on the spawning thread's end — a pool
thread). Not the capper's group (only GNU `timeout` without `--foreground` signals its group; `kill -9 <pid>` does not;
one group for all would lose stop_tree's one-command stop). TERM, INT and HUP at the CLI stop the run synchronously
through the same guard (`stop_on_signals`, `__main__` only) and print a NO-GO line, exit 128+signal. A command that
ended is dropped from the guard before anything else, so a late signal never reaches a finished scope. The 4 s grace
(stop_tree keeps its 15 s for a timed-out case) keeps the worst case inside Verify 1's 5 s; a runner whose teardown
needs longer is KILLed — named, not measured on any scope today. Full record: tasks/toolkit_local_diff.md item 14.
