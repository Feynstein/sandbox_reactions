## Late finding (the lead, after the claim run): the smoke leaked onto the real desktop
The lead saw one window with the step counter (1 to 6) on their screen while `--changed` ran. Cause (confirmed against launch.py, which drops
WAYLAND_DISPLAY for the same reason): this is a Wayland session, winit prefers Wayland whenever WAYLAND_DISPLAY is set, so `xvfb-run` alone did
not keep tests/capture/check.sh's `smoke` inside the Xvfb. My own manual runs (three, outside the harness) leaked the same way. Fix:
check.sh now runs the app as `xvfb-run … env -u WAYLAND_DISPLAY -u XDG_SESSION_TYPE <bin>`. NOT RUN since — the capture scope needs one more
run, the lead's, watched, after which no window should appear: `python3 tools/pb/verify.py capture --task M0-T8e`.
