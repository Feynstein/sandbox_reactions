Run on laserax-ai (linux-pc), RTX 5090; model=claude-opus-5-5 level=high (rung_record now; matches the heading). Start:
`plan.py show` baseline 2026-10-20T19:20:30-04:00, 512 files. No calibration process ran on the box during the task (`ps`, 19:2x);

## What changed
- `headless.rs`: `Args.continue_life` (`--continue`, refused without `--load-dump`); beside every dump of a GPU run (`--dump-every` and
  the final one) `dumps/s_<step>.observers.json` = `{version 1, step, sim_time, scene, world [w, h], done, wall_s, dt_next,
  heat_unconverged, watch, ledger}`, written after the dump, `.tmp` renamed into place (`observers_path`, `Carried`, `read_carried`).
  `--continue` reads it after the scene is prepared, before the calibration gate and any GPU (exit 4: missing, not JSON, version,
  step index or sim time bits, scene label, world, `done` past the step, any field unreadable); then `done`, `wall_s`, `dt_next`,
  P5's count, `Watch` and `Ledger` go on, `first` = the life's start step (so `at.step`, `--dump-every`'s alignment and the progress
  tick read as in the cut run), `--steps` / `--max-steps` count the whole life; the ledger's start restored means no single-step
  first chunk. The heat-unconverged count is kept by `execute` itself now (every warning, printed or not); a counting
  (`calibrate`) run adds the carried count to `unconverged_steps()`.
- `watch.rs`: `Watch::snapshot` / `restore` — tracker, stages, last_sim, events (detail's numbers exact, its `stage` a string),
  lives, remnants, ended, marks, max_gas_speed.
- `ledger.rs`: `Record::json` now `json_with(num)` (the summary's output unchanged), `Record::restore`, `Ledger::snapshot` /
  `restore` (booked, the four accumulators, start, last).
- `tracker.rs`: `exact` / `read_exact` (f64 ↔ a JSON string of Rust's shortest round-trip form — serde_json's number parse is
  best-effort, `float_roundtrip` off, §1.2 untouched), `read_whole`, `read_list`; `Object` derives `Default`, `Object::snapshot` /
  `restore` (one field table both ways), `Tracker::snapshot` / `restore` (next_id, previous blocks and weights, objects).
- `stages.rs`: `StageTracker::snapshot` / `restore` (ignited, last_collapse, raw, streak, shown, fired), `Stage::from_id`.
- One-liners outside the block's list: `calibrate.rs` and `tests/gpu/calibrate_bisect.rs` (`continue_life: false` in their `Args`
  literals), `tests/gpu/dump.rs` (the dumps/ listing keeps `.bin`), `tests/gpu/cold_core.rs` (`series` reads `.bin` only), sr-app's
  usage line (`[--load-dump FILE [--continue]]`).
- Contract §0.5 [M0-D76] + in-place notes in §2.12.3 and §3.3; plan Superseded mirror; testing.md (`observe_run` row, `dump` row's
  listing note); running.md (§ The binary, headless).

## Choices (declared)
- Where: the sibling file `dumps/s_<step>.observers.json` (the block's first option). Inside the dump would break the `dump` scope's
  byte-for-byte resumes without `--continue` (fresh observers → other bytes) and §2.12.3's refusal of unknown header keys.
- Exactness by strings, not numbers: the snapshot's f64s are `"1609.48"`-style strings; ±inf and NaN survive too.
- The case runs the Sun-like preset built in code through `run_scene_captured` (calibrate's path), not `--scene preset:sun`: with
  assets/calibration.json partial every `preset:*` scene is exit 6 on this tree (O13).
- `--continue` checks scene label, world and the step (index and sim time bit for bit); it does not compare the other arguments
  (`--until`, `--dump-every`, `--edge`): "the same chunks and frames" holds when the cut run's command is given again plus
  `--load-dump FILE --continue` (running.md says so).

## For M0-D77 (calibrate's checkpoint)
- The pair today: headless writes a dump with plain `fs::write`, then the snapshot to `s_<step>.observers.json.tmp` and renames it.
  A torn dump is refused by `Dump::read` (exit 4); a dump with no snapshot, or with an older step's, is refused by `--continue`
  (exit 4). Every `--dump-every` multiple keeps its own pair (~13.4 MB + the snapshot, 600 × 400): a `<life>/checkpoint/` that keeps
  only the last pair is yours to arrange (headless has no "replace" mode).
- Continue through calibrate's own path: `Args { load_dump: Some(dump), continue_life: true, .. }` with the same `scene` label
  (`calibrate:<label>:<mass .3>` — the snapshot's `scene` is checked, so the mass is too), `until`, `max_steps` (counted over the
  whole life under `--continue`) and `dump_every` as the cut run; `run_scene_captured` takes it as is.
- Not in the snapshot: the adapter, the driver and the physics_hash (your block's guard: add them to the snapshot with a §0.5 line
  extending [M0-D76], or keep them beside the checkpoint); calibrate's own progress `stages` list (the tick closure's, written to
  progress.json) — carry it yourself; the `--timing` costs.
- On a counting run (`run_scene_captured`) the carried heat-unconverged count is added to `unconverged_steps()` at the start, so the
  progress lines go on counting from the cut. The progress hook does not tick at the continued-from step (`ticked` starts at
  `step / every`, as a run starting there).
- A continued life whose restored state already met its `until` does not stop at once: the condition is read on a frame, so it stops
  at the first frame after the cut where it holds (an event condition needs a fresh event — a `core_collapse` that fired before the
  cut will not fire again; `Watch::holds` reads `fresh` events). Your "ends at once" needs its own check.
