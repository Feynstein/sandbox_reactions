## What exists now
- `tools/pb/launch.py`: a service may declare `port_range: [first, last]`. `start` finding `port` held by a process it did not start takes
  the first free port of the range (not the held one), swaps `port` as a whole argv word and in `ready_url`, logs it, records it
  (`entry.port`), prints `<name>: ready on port <n>, …(port <p> held by a process we did not start)`; `status` says `on port <n>`.
  No `port_range` → the old refusal, word for word; a range with nothing free → refusal naming the range. Selftest: 51 checks (+5).
- `tools/pb/launch.json` `web`: port 47840, `port_range` [47840, 47859] — clear of the game's 47811–47830, and off 47812 (VS Code's).
- `tests/web/check.sh`: reads the printed port for the smoke; new case `ready-held` (a foreign listener on the first port; the server
  must take another, the foreign process stays, the page reaches ready there); port lock renamed `sr-web.lock` (also in smoke.sh).
- `tests/smoke.sh` launcher case: the decoy web server's port read from its start line; `_sr_port_closed` on that port.
- `web/smoke.mjs`: default `--base` 47840 (check.sh always passes it).
- Contract: §0.5 [M0-D107], §3.4 Web, §3.6 `web` row; mirror in m0_superseded.md; docs/agent/testing.md rows; verify.json `web` scope
