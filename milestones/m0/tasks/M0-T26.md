## The contract change (asked, answered)
§2.12.3's header could not carry a bit-identical resume: the latch's arming time (`since`), Δt_{n+1} and the box are on
the GPU only, and none can be rebuilt from the cells. The lead's answer, 2026-10-11: «Add one header key (Recommended)».
The header gains `resume: {dt, dt_next, latch_since, box[8], box_args[6]}`; version stays 1. Measured in the scope's
control: every record restored but `latch_since` (set to 1.0, i.e. armed) → the flag 2 Δt after the dump's fire fires
(`steps_run 2, latch_fired Some(2)`) where the straight run runs 50.

## Defaults taken (cheap to reverse) — §2.12.3 / §3.3 do not settle them
1. `step` is the GPU's step count (the next step's index), read from the Δt record — under frames the CPU count runs
   ahead after a latch stop. `--dump-every N` dumps at every step index N divides, counted from the scene, so a resumed
   run's dumps land on the straight run's names; `--steps N` with `--load-dump` is N more steps.
2. `--load-dump` takes world and cells from the dump; the scene still gives constants, edge and switches; a `--world`
   other than the dump's is exit 4. `--dump-every` without `--out` is exit 4.
3. `sinks` is written `[]` and read (≤ 16, five finite numbers each); `load_dump` refuses a dump holding a sink until P3
   has sink state.
4. The booking (ledger terms, frame accumulators) is not in the dump: a resumed ledger restarts (§2.9 "since the ledger
   (re)started"). It feeds observers only (§1.3.4), so the state stays bit-identical.
5. headless's `sim_time` is the dump's (0 without one): summing Δt into sim time in headless is still not built (M0-T20's
   note); frames (`poll()`) carry it and the dump restores it.

## Found and handled

  correctly rounded parser (`exact_number`). The dependency table (§1.2, FROZEN) is untouched.
