# M0-D131 — launch.py's records under a lock, merged per entry (linux-pc, 2026-10-31)

Ran on: claude-opus-5-5, high (rung_record.py now). Box: linux-pc (laserax-ai). The lead's word on the toolkit change, asked
first as the block says: «Go: lock + merge (Recommended)».

## Cause (measured, then read)
- Baseline, before the fix: probe (c) (scratch `probe_c.sh`: `launch.py start web` + `start headless-boot` at once, then both
  `stop`s at once, the records read after each, the 478xx listeners after the stops), 6 rounds → 6 bad: `web`'s record lost
  (rounds 1, 4, 5; a server left bound in 1 and 5), and the parallel stops brought `headless-boot`'s entry back (2, 3, 6) —
  the stops race the same way as the starts. logs/M0-D131.log.
- Read in tools/pb/launch.py (the block's own file): `Context.__init__` reads the pid file once; `Context.save` writes the
  whole `self.pids` back, so a run's write erases every entry another run wrote since its read; `write_pids` uses one fixed
  `<pid_file>.tmp`, so two writers at once interleave in it — the «Extra data» torn JSON of M0-D128's round 5.

## What changed
- tools/pb/launch.py: `records_lock(path)` — `<pid_file>.lock`, `fcntl.flock` on POSIX, `msvcrt.locking` on Windows,
  non-blocking tries with `pause`'s backoff, over `LOCK_WAIT_S` (30 s) a WriteRefused naming the lock (so the verbs' existing
  verdict path names it, never a hang). `Context.seen` keeps the records as last read; `save` re-reads under the lock and
  sets / drops only the names whose entry differs from `seen`, writes, then takes the merged file as its new `pids` and
  `seen`. Callers unchanged: an entry mutated in place (`exit`) still reads as changed; `cmd_smoke`'s `entry is not before`
  holds since the entry objects this run set are carried into the merged dict.
- Selftest: « 8 starts at once on one pid file: each GO, every record kept » and « 8 stops at once on one pid file: each
  GO, no record left » (eight `exit` services through the real CLI, spawned together).
- tests/plants/tools-selftest-launch-records.patch (verify.json, case `launch`): the merge over `seen` instead of the file
  as it is now — the lock kept, the lost update back.
- .gitignore: `tools/pb/.launch.pid.json.lock`. tasks/toolkit_local_diff.md: local diff 10.
