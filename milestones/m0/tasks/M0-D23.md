# M0-D23 — the harness gives its scopes Git's bash on win-laptop

Box: win-laptop (Laser2025-20), Windows PowerShell 5.1, `py -3.12`. Model: claude-sonnet-5-5, high (rung_record.py now).

## Cause
`argv_of` resolved a bare `bash` with `shutil.which` on the caller's PATH; from a plain PowerShell window that is
`C:\WINDOWS\system32\bash.exe`, WSL's relay (no `/bin/bash`). The scripts then also lacked Git's `usr\bin` tools and `~/bin`'s rsync.

## Change (tools/pb/verify.py only)
- `tool_path(environ=None)`: on `nt`, Git's `usr\bin` (found from `git.exe`'s parents, else `%ProgramFiles%\Git`) and `~/bin` are put
  first on PATH; elsewhere PATH is returned as is.
- `argv_of` looks a bare command up with `path=tool_path()`; `case_env` sets `env["PATH"] = tool_path(env)` so every spawned
  command (and the red-arm plant commands) inherit it. The caller's window is never changed.
- Local fix the v12.3 annex lacks: flagged to M0-TZ (Carried flags), like M0-D16's `PB_PYTHON` (toolkit_local_diff.md).
