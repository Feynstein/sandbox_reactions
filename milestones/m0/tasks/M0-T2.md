### Findings
1. wgpu's HighPerformance pick with SR_TEST_ADAPTER unset is the Quadro RTX 4000, not the 5090. A physics scope
   (R12: physics on the 5090) must set SR_TEST_ADAPTER itself — flagged to M0-T3, the next GPU module.
2. A query matching several names (e.g. `rtx`) takes Vulkan first, then wgpu's list order — a declared default;
   contract §6.1 is silent on it.
3. The two-backend preference is proven on the fixed list only: linux-pc lists no adapter on two backends.
4. win-laptop's list (RTX 4080 Laptop, Intel Arc, WARP where listed) — NOT RUN, owed on win-laptop (R15); the live
   case hard-codes the expected names by `cfg!(windows)`.
5. M0-T1's note stands: eframe's wgpu path may re-enable webgl/gles by cargo feature unification — flagged to
   M0-T5, which adds eframe to sr-app.
