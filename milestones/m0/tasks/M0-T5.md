## What exists now

  (`cfg(not(target_arch = "wasm32"))`): `run()` — `--adapter` through `sr_engine::gpu::match_adapter` in egui-wgpu's
  `native_adapter_selector` (and the pick must support the window's surface), no flag → egui-wgpu's high-performance
  request against the surface (§6.1); device at `Limits::default()`, no feature; `--offscreen-window` → position

- `crates/sr-app/src/status.rs` (new, native-only): `--status-port <p>` binds 127.0.0.1:p before the window, a thread
  answers HTTP/1.0 `GET /status` with §3.4's JSON (`status`, `frame`, `step`, `sim_time`, `adapter`, `fps`); 404/405
  otherwise; one unit test (`cargo test -p sr-app --bin sandbox-reactions` — no scope runs it; the `desktop` scope is
  the graded check).
- "ready" = the first presented frame: `ui()` asks egui for a `ViewportCommand::Screenshot` every pass until an
  `Event::Screenshot` arrives. egui-wgpu only captures a frame whose surface texture it acquired, and calls
  `queue.present()` on that frame right after starting the copy; the event is read a pass later, so it proves a frame
  was acquired, drawn and presented. A frame that fails to acquire (Occluded, Lost, Timeout) drops the request, and the
  app asks again. Measured on Xvfb/lavapipe: booting at frames 0–2, ready from frame ~3–5, ≈ 0.3 s after spawn.
- `crates/sr-app/src/main.rs`: no subcommand (or a desktop flag first) → `desktop::run`; exits 0 / 3 (any eframe or
  wgpu error, `SR-ERROR …`, status set to "error" first) / 4 (bad argument, a later block's flag such as `--world`,
  `--capture`, `--measure-ui`, or a status port that cannot be bound).
- `crates/sr-app/Cargo.toml`: eframe, wgpu, serde_json (all approved, workspace versions). Root `Cargo.toml`: eframe's

## The override (PLAYBOOK §9) — asked and answered
eframe 0.36.2's `wgpu` feature = `wgpu_no_default_features` + `egui-wgpu/default`, and egui-wgpu's default turns on
`wgpu/default` and `wgpu/webgl` (so `gles` too). With it, `cargo tree -e features -i wgpu` showed `webgl` and `gles` —
against §1.2's "no `webgl`". The lead chose `wgpu_no_default_features` (2026-10-09). After: wgpu's features are
dx12, metal, std, vulkan, web, web-sys, webgpu, wgsl (all targets). Written in contract §0.5 [M0-T5] and the plan's
Superseded section.

## Declared defaults (cheap to reverse)
- `game-offscreen` also takes launch.py's private Xvfb on Linux: Wayland ignores a window position, so without it
  the off-screen variant would open on the lead's desktop (R4). On Windows the `xvfb` key is inert (platforms linux).
- Off-screen position (−20000, −20000): no monitor arrangement reaches that far; not read from the monitor list
  (eframe creates the event loop, so the monitors are unknown before the window exists).
- `frame` counts `ui` passes; `fps` = frames in the last second (egui's clock); `step` 0 and `sim_time` 0.0 until the
  world runs in the window (M0-T84); `adapter` is the adapter's name.
- The app repaints continuously (a running simulation will); on lavapipe ≈ 235 fps under Xvfb.
- A port that cannot be bound is exit 4 (an argument the box cannot honour); launch.py refuses a held port earlier.
