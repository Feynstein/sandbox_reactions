# M0-T86 — the banner and the automatic slow-down in the app

Built on linux-pc (laserax-ai, lavapipe), Sonnet 5.5, high.

- `crates/sr-app/src/ui/banner.rs`: `view(&TimeControl) -> Option<Banner>` (the text of `time.banner()`'s event, byte-exact from
  strings.rs) and `Feed`, the door of the slow-down's two sources: `latch()` for a frame the latch cut (core collapse, ×0.1) and
  `event(time, object, kind)` for the observers' events (`ignition`, `core_collapse`, `supernova`; `sink_formed` and `ending` are
  ignored). Each (object, event) is booked once (§1.9.4); a Tracker `core_collapse` that follows a latch cut is the same collapse and
  is swallowed once (`latched`), so a player who already sped up sees no second banner. The clock (`TimeControl::on_event`) stays
  the one place that says only-slower, the rung and the setting off.
- desktop.rs: `Sim` now holds `sr_engine::watch::Watch` (the observers the headless run uses, so M0-T92's star readout reads the
  same objects) and a `Feed`; `poll()` takes `Step::poll_frames` (report + block summary per frame): `on_report`, then
  `Feed::latch` when the frame was planned and cut, then `Watch::update` and each fresh event into `Feed::event`. The banner is
  drawn over the world's top centre in the CentralPanel (banner.bg / banner.text, 20 px). A forced (capture) frame is never
  planned, so its latch is not fed.
- Scope `ui_banner` (R17; the plan spells `ui-banner`): 12 cases, `bash tests/cpu.sh sr-app --bin ui::banner`; plant
  tests/plants/banner-wrong-event.patch (a core collapse worded as a supernova) → red-armed, 2 failed.

Not proven: the banner on screen (a collapse or supernova is not reachable on lavapipe in a capture's time; TV2 marks it), and the
per-frame cost of `Watch::update` on the real GPU (it decodes the whole block summary every frame; nothing blocks on it, M0-TJ2).

tools/pb/verify.json: the `ui_banner` entry added after `ui_topbar`; an early re-dump through python reformatted the whole file,
so the untouched scopes' text was put back from HEAD verbatim — the file's diff shows only the entries M0-T84–M0-T86 changed
(`box` lists of desktop and capture and the `ui_banner` block are written in json.dump's layout rather than the inline one).
