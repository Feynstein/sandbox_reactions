# M0-T56 — the block summary

Ran on linux-pc (laserax-ai), RTX 5090 (Vulkan), 2026-10-15; `rung_record.py now` → model=claude-opus-5-5 level=high
(the heading's rung, Opus 5.5, high).

## What exists
- `crates/sr-engine/shaders/summary.wgsl` (new): two dispatches over the box's 8 × 8 tiles (indirect, `ARGS_TILES`),
  workgroup 2 × 2, one invocation per 4 × 4 block, 16 cells in row-major order added in f32, no atomic.
  `summary_cells` (state, φ, EOS group): mass, Σx·m, Σy·m (cell centres i + ½), momentum, kinetic (½|p|²/Σ), thermal
  (Σ ε_th, ε_th = E/Σ − ½|u|² − ε_cold as stored), cold (Σ ε_cold), ∫Π dA, the ten species masses, Σm·φ, unbound mass
  (½|u|² + ε_th + φ > 0), and the max-Σ cell (first in row-major order → the lowest y, then x): index y·W + x, Σ, T
  (μ ε_th floored at T_floor), X, Π_cold/Π. `summary_book` (no EOS): the accumulators (radiated, nuclear H…N, ν lost,
  ν deposited) and a 16-bit mask of the sinks whose position lies in the block. Split in two so each stage binds ≤ 8
  storage buffers (§6.2.2): one dispatch would need 10.
- `crates/sr-engine/src/summary.rs` (new): `Summary` (built by the step), `Block` (46 fields, 48 words), `BlockSummary`
  (origin, size, columns, blocks row-major, the sinks the masks index), `Frame { report, summary }`.
- `step/latch.rs`: `encode_frame` clears the accumulators at a frame's start when a summary is pending, then the steps,
  then the summary after `latch_end`, outside the frame's timing. The readback buffer grows by the box record, the
  sinks' 136 words and the whole blocks buffer, placed after the timestamps' room. `poll()` is unchanged (summaries
  dropped). The new `poll_frames()` returns `Frame`s.
- `step/mod.rs`: the step builds its `Summary` (φ: P2's side fields, else P3's, else none → read as 0; the sinks' state
  buffer when P3 runs); `init_buffer`, `record_dispatches`, `compute_pipeline` now `pub(crate)`.
- Scope `summary` (7 cases), plant `summary-skip-row`; testing.md row.

## Readings and defaults (declared, cheap to reverse)
1. "The accumulators reset after each summary": reset at the **next frame's start** (`clear_buffer` of booking.heat,
   booking.reactions, booking.neutrino_heating, exactly the accumulator terms — asserted at build). Between frames the
   booking still holds what the last summary summed. An end-of-frame reset would break nu_heat's
   `gpu_a_stopped_frame_runs_no_p7_after_it` (a stopped frame's booking against a bare run's, bit for bit).
2. `FrameReport` stays `Copy`, and seven test modules index `reports[0]`. The summary rides in `Frame` from `poll_frames()`.
   §3.1 lets the builder pick the exact Rust types.
3. "The sinks inside" = a slot mask per block plus the sinks list in the summary: what §1.9.2 needs (sink inside, heaviest
   sink, sink mass).
4. A frame whose last step's P5 carried over (§0.5 [M0-TJ4] (6)) is summarised as the state stands, with the held step's
   P0–P4 in it. Each accumulator value is still summed exactly once.
5. Without φ (no P2 and no P3), φ reads 0: Σm·φ = 0 and the unbound mass is the cells with ½|u|² + ε_th > 0.

## Findings measured, not acted on
- Readback size: the whole world's blocks buffer is copied every frame, because the CPU learns the box only from the
  copy: 2.9 MB at 600 × 400, 48 MiB at 2048². The cost of the copy and of the summary pass is not measured, and the
  summary is outside the frame's timing, so `cost` does not show it. Whoever wires `Engine::poll` / R3's frame budget
  should time it.
- Sizing: ≈ 925 new lines (shader 253, module 264, test 407) and 7 code files (3 new, plus lib.rs, mod.rs, latch.rs and
  main.rs). That is over §2.1's ≤ 600 / ≤ 6. The Deliver line's three files and seven-case test are already that size.
  Not split: one thread, green.
