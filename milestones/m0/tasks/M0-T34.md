## What exists
- `crates/sr-engine/shaders/hydro.wgsl` — M0-T33b's twin in f32, two entry points over the box's 8 × 8 tiles
  (`Size::Indirect(boxfit.args(), ARGS_TILES)`, `abox` uniform):
  - `hydro_update`: per cell, the twin's scheme step for step — `read_cell` (Σ < Σ_vac → the floor state, as dt's
    `cell_rates`), `read_at` (bounce ghosts: the mirror cell, its normal velocity negated), MC slopes with the species'
    shared limiter factor, four face states, `cons`, the Hancock delta from both axes, `evolved` (falls back to the
    unevolved face when the predicted one is not a state), HLL-Davis with species by the mass flux's upwind side, `wall`
    (mass, energy, species 0; normal momentum = the face's Π). A cell recomputes its four neighbours' predicted faces
    (`cell_faces`) instead of reading a stored face set; it writes the **next state** (P4's own three buffers, the state's
    packing), never the state it reads, so no invocation sees a half-updated neighbour. A cell and its four neighbours all
    below Σ_vac is copied unchanged (`keep`).
  - `hydro_commit`: next state → state over the box.
  - Storage buffers in `hydro_update`: state ×3, next ×3, the Δt record, eos.wgsl's table = 8, WebGPU's limit (§6.2.2).
  - The flux arrays use constant indices only (`if dir == 0u`): an index from `dir` keeps a WGSL array out of registers.
- `crates/sr-engine/src/step/hydro.rs` — `dispatches(device, state, eos, boxfit, dt_record) -> Vec<Dispatch>` (the next
  state's buffers live in the bind groups).
- `crates/sr-engine/src/step/mod.rs` — `Passes { mode, gravity: Option<&SideFields>, hydro: Option<EdgeMode> }` and
  `Step::with_passes` (refused as `with_gravity` is); `new`, `with_box`, `with_gravity` keep P4 **off**, so lot 3–4's
  scopes, which build steps that way, are unchanged. P4 fills `Pass::Hydro`'s slot.
- `crates/sr-engine/src/headless.rs` — the scene's `hydro` switch turns P4 on (`switches.hydro.then_some(edge)`).
- `crates/sr-engine/tests/gpu/sod.rs` — 6 GPU cases (`gpu_…`) beside the twin's 9; the twin's shock and L1 code now
  shared helpers `shock_at(rho, t)`, `l1_at(rho, t)` (same numbers, same prints); `gpu_run(physics, start, Until)`.
- `tests/plants/hll-swap.patch` — a second hunk: the shader's `hll` takes `let r = l;` too.
- `tools/pb/verify.json` scope `sod`: expected 9 → 15, desc; `docs/agent/testing.md` row updated.

## Deviations and decisions
1. **Bounce under both edge modes.** §2.8's *leave* is M0-T35's (its Deliver). `Passes::hydro` carries the edge mode but
   P4 ignores it; headless scenes in *leave* (sun_disk.json, every preset) now run P4 with bounce walls. Matter there is
   far from the world's edge for many steps, but a leave scene is not yet a leave run.
2. **Neighbours' faces recomputed, not stored.** A stored face set is 4 faces × 15 words = 60 words a cell (+1 flag):
   at §2.8's largest gravity-off world (2048², 4.2 M cells) ≈ 1 GB, past WebGPU's 128 MiB binding × the 4 storage slots
   left. The recompute needs only a next-state copy (the state's size, three buffers ≤ 84 MB at 2048²). It costs ≈ 5× the
   predictor per cell — the cost above.
3. **P4 opt-in in the step API**, on by default only through headless's switch: tests that build steps with `new` /
   `with_box` / `with_gravity` keep their lot's behaviour.
4. **Two other scopes' oracles moved with headless** (the first claim run, NO-GO): `timing`'s
   `headless_timing_writes_every_pass_of_the_nominal_disk` builds its expected pass list from `disk()`, and `dump`'s
   `a_headless_run_writes_one_sim_time_in_its_summary_and_its_final_dump` re-runs headless's step in-process — both
   built the step without P4, so headless's P4 read as a missing pass and a different state. `disk()` (timing.rs) and a new
   `Run::as_headless` (dump.rs) now build the step headless builds (P2 + P4); no case, count, plant or tolerance changed.
   `verify.py timing dump` GO 13/13; `--redarm timing` GO (timing-skip-pass RED), `--redarm dump` GO (both plants RED).
5. **M0-TM5 filed** (the rating refresh): my three flags to open BUILD blocks brought the count since M0-TM4 to five;
   `plan_lint` read NO-GO until it was filed, after this block, to run next.

6. **M0-D28 filed**: the second claim run read `web[ready]` NO-GO — ERR_CONNECTION_REFUSED while `web[no-webgpu]`, run
   in parallel, stopped the shared server (logs/M0-T34.web.log from line 27); `verify.py web` GO on two re-runs (task ids
   M0-T34-web1, -web2). Not caused by P4 (the wasm build compiles hydro.wgsl's crate, but the failure is the page's TCP
   connect). Filed after M0-TM5.

## Not acted on (findings)
- **P4 dominates the step:** ≈ 1.0 ms of ≈ 1.2 ms on the Quadro for a ~100 × 100 box (the 4080 Laptop's whole step was
  0.257 ms before P4, M0-V4). A tiled `hydro_update` (8 × 8 tile, its 12 × 12 primitives in workgroup memory, 8 KB, the
  predicted faces exchanged through it) would remove most of the 5× recompute and the 25 `read_cell` EOS evaluations a
  cell. Not built: it is a second thread (performance, not the scheme), and G-TOP / M0-R3's top-speed budget, not this
  block, says how fast P4 must be. Flagged to M0-V5.
- The `timing` scope's log is `logs/<task>.timing.log`: a task that names its own timing log so loses it to the claim.
- The `gpu` test binary warns `fields sigma, mom, mass_out, energy_added are never read` (another module's struct, not
  this task's).
