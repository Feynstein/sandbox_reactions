## What exists
- `crates/sr-engine/src/calibrate.rs`: `--resume DIR` (`Opts.resume`). `Lives` continues in DIR instead of a new stamp; `Lives::run` first
  asks `Lives::replay` (while `replaying`): run NN reads `DIR/<label>-<NN>/summary.json` when it parses, `until.met` is true and `scene` is
  `calibrate:<label>:<mass to 3 decimals>`; the run line then reads `… wall_s=<the old life's> replayed record=<DIR>/<label>-<NN>`. The first
  run with no finished record turns `replaying` off — it and every run after it run fresh in DIR, the numbering continued. `read_life` split
  into read + `life_of(&Value, mass)` so a replay and a fresh run build their `PresetRun` the same way (stages, at_x_h, max_gas_speed, adapter).
- Refused, exit 4, «`<DIR>` is not this calibration's: start without --resume»: a record whose scene names another label or mass; a record
  whose adapter name does not contain `--adapter` (case-insensitive, as `gpu.rs` matches); run 1 finding no `<label>-01` folder in DIR
  (another item's DIR — see Deviations). `--resume` on a path that is not a folder: exit 4 «not a folder», before any run. Items 1–2 (no lives)
  ignore it, the folder check included. Without `--resume` nothing changes.
- A file cut while it was written does not parse: no record, the life runs fresh (case: a half-written summary.json).
- sr-app's usage line, running.md (§ Calibrating: the `--resume` paragraph; the `calibrate` bullet), testing.md's `calibrate_bisect` row,
  contract §3.3's Calibrate line + §0.5 `[M0-D72]` (the lead's words, 2026-10-20, at M0-V9) + the mirror in the plan's Superseded.
- Scope `calibrate_bisect` 8 → 9 cases: `a_stopped_item_resumes_without_rerunning_a_finished_life` (4 short real lives: the unbroken two, the
  second re-run twice after its record is removed / half-written). Plant `calibrate-resume-any-mass` (the scene match removed) in verify.json.

## Deviations (declared)
- **A DIR without `<first label>-01` is refused** (not in the Deliver text, which only names records read at `<label>-<NN>`): with only
  the folder-per-label naming, `--resume` of another item's DIR would find no record at run 1 and silently start a whole stellar life
  in the wrong folder. `headless` makes a life's folder before it runs, so a cut first life still leaves `<label>-01/`; a DIR with none
  cannot be this item's.
- The value/file equality in Verify 1 is graded on the run sequence and the exit-6 error (an unbroken m_ign bracket whose ends agree writes no
  file); a bisection that completes and writes the file was not run — it needs lives of minutes each (NOT PROVEN beyond the two-run
  sequence). `bisect` itself is unchanged and graded by its stubs.
