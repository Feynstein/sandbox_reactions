# M0-T30 — the GPU FFT (detail)

Box: win-laptop `Laser2025-20`, physics adapter NVIDIA GeForce RTX 4080 Laptop GPU (Vulkan), device at WebGPU's
`Limits::default()` (M0-T2's helper). Model claude-opus-5-5, level high (`rung_record.py now`).

## What exists
- `crates/sr-engine/shaders/fft.wgsl`: one row or one column per 256-invocation workgroup, held in
  `var<workgroup> buf: array<vec2<f32>, 2048>` — exactly 16,384 B, the only workgroup variable. Twiddles: one storage
  table of e^{−2πi k/2048}, k < 1024, taken in f64 on the CPU; length n reads every (2048/n)-th entry, no cos/sin in the
  shader. Decimation in time (bit-reversed in, natural out) and in frequency (natural in, bit-reversed out).
  Entry points: `rows_c2c`, `columns_c2c` (a 2D transform in place, `FftParams.inverse` picks the direction, the inverse
  ÷ n per axis); `conv_rows` → `conv_columns` → `conv_rows_inverse` (the convolution).
- `crates/sr-engine/src/step/fft.rs`: `Fft::new` / `Fft::transform(device, data, nx, ny, inverse)` → 2 dispatches;
  `Convolution::new(device, kernel)` / `Convolution::dispatches(device, queue, src: Plane, dst: Plane, stride, Region)`
  → 3 dispatches; `Convolution::spectrum` (sampled at signed offsets in f64, stored f32, transformed on the GPU, own
  submit, cached per (nx, ny)); `cached_sizes`; `padded(len)`; `encode`; `read_back`; `FftError`
  {Length, BoxAxis, Outside}. Conventions are the twin's (row-major, forward unnormalised, inverse ÷ N, kernel
  K(dx, dy) with dx = x_target − x_source).
- The convolution: (1) the box's h rows from `src` (offset + (y0 + row)·stride + x0), zero-padded to nx, forward — the
  padded rows h … ny − 1 are zero and never transformed, the work buffer is nx × h; (2) each column forward over ny,
  × K̂ / (nx·ny), inverse by DIF in the same dispatch — only rows < h kept; (3) the h rows inverse by DIF, the real part
  of the box's cells into `dst`; cells outside the box are never written (tested with a sentinel).
- The geometry uniform has reduce.wgsl's `ActiveBox` layout (x0, y0, w, h, fft_w, fft_h, from_step, fits), and every
  entry point returns early past the box's rows / columns.
- `tests/gpu/fft.rs` (scope `fft`, 8 cases), plant `tests/plants/fft-gpu-bitreverse.patch` (bit reversal shifted by one).

The small box is dispatch- and submit-bound (3 dispatches + 1/20 of a submit); the Quadro's own numbers are M0-T31's.

## Deviation
- The block's parenthesis expected a multi-pass scheme at 2048 ("does not fit … with anything else"). Nothing else is
  kept in workgroup memory (twiddles in a storage table, indices computed), so a 2048-point row fits one workgroup
  exactly at 16,384 B — TW's bench did the same — and every size is one pass per axis: fewer dispatches, the block's
  stated aim. The device is `Limits::default()`, whose validation would refuse a pipeline over the limit.

## For M0-T31 (flagged)
- The geometry uniform is `ActiveBox`-shaped and the entry points exit past the box, so P2 can bind
  `boxfit.active()` as binding 0 and dispatch by the box's sizes (indirect args for h rows and fft_w columns would need
  two new words from `box_fit`) or over-dispatch to the world's maximum — no readback. The kernel transform is still
  chosen per size on the CPU (`Convolution::spectrum`): M0-T21's flag stands.
- Σ_src (Σ ≥ Σ_vac, else 0) is not in the shader — `conv_rows` reads the plane as is; P2 adds the mask (one compare in
  `conv_rows`, or a masked plane).
- `Convolution::spectrum` submits on its own the first time a size is used; inside a frame, warm the sizes first.
