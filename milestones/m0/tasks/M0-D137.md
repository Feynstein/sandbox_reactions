# M0-D137 — the capture `hover` with a cell off the world

Ran on linux-pc (laserax-ai), lavapipe, model=claude-sonnet-5-5 level=high.

## Cause (confirmed)
`scripted_hover: Option<[u32; 2]>` was passed whole to `Sim::set_hover` through `.or(hovered)`: an off-world cell was a `Some`, so
`hover.and(reading)` kept the previous reply. The real pointer path (`cell_at`) already returns `None` off the world.

## Change
- crates/sr-app/src/desktop.rs: `scripted_hover: Option<Option<[u32; 2]>>`; `Action::Hover` stores `None` for x ≥ width or y ≥ height;
  the frame reads `self.scripted_hover.unwrap_or(hovered)`.
- tests/capture/actions.json: step `hover-outside` after `hover` (`[700, 500]`, 3 frames) — 22 steps.
- tests/capture/check.sh: DONE 22, WANT list, the right panel of `hover-outside` holds > 100 fewer lit pixels than `hover`'s.
- tools/pb/verify.json: capture desc + plant `capture-hover-off-world`.
- tests/plants/capture-hover-off-world.patch (new); capture-hover-ignored.patch re-cut against the new arm.

## Measured
- Before the check was loosened: hover-outside 7037 lit vs select 6650 — select reads «Empty space» (no scripted hover), the outside
  panel the longer «Hover over a cell to inspect it.», so select is not a bound; dropped.
- Plant capture-hover-off-world: hover-outside 10135 lit = hover's 10135 → RED with the stale-reading message.
- `verify.py capture --case actions` GO; `--redarm capture` 8 plants 8 red (logs/M0-D137.capture.redarm.log).
- Not run: win-laptop (R15) — the capture route there is `--offscreen-window`; same code path.
