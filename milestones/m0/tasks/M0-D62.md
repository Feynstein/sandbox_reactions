## What changed
- `crates/sr-physics/src/calibration.rs` — `Calibration::render_reserve_ms` is `Option<f64>`: `parse` accepts a file without
  the key (`None`) and still refuses a present one that is not a finite number ≥ 0 (negative, `null`, a string); `to_json`
  leaves the key out while `None`; `test_calibration` keeps `Some(3.0)`. `TimeControl::new(top_rung, render_reserve_ms)`
  already took an `Option` (3.0 ms on `None`, §1.8.3), so the field passes straight through. `EMBEDDED` is now
  `include!(concat!(env!("OUT_DIR"), "/embedded_calibration.rs"))`.
- `crates/sr-physics/build.rs` (new) + `crates/sr-physics/src/calibration_embed.rs` (new, `calibration::embed`) — the build
  script writes `Some(include_str!("<assets>/calibration.json"))` when the file exists, else `None`. It watches the
  `assets/` folder, not the file: cargo reruns a script on every build while a watched file is missing, which would rebuild
  sr-physics and everything above it every time until the first calibration. The chooser is one dependency-free function
  that build.rs compiles by `#[path]`, so the `calibration` scope tests the same code.
- `crates/sr-engine/tests/gpu/calibration.rs` — two cases (10 → 12): the reserve-less file (accepted, round trip without
  the key, `resolve` and `calibration_gate` open for a preset, `TimeControl` identical to one given 3.0, present reserves
  still checked, a measured 4.25 written back); the embedding (`embedded_source` on a folder without and with the file, and
  this binary's `EMBEDDED` present exactly when the tree's file is). The existing embed case's message now names build.rs.
- `tests/plants/render-reserve-required.patch` (new) — `parse` requires the key again.
- `tools/pb/verify.json` — `calibration`: expected 12, the plant, its path, the desc.
- `crates/sr-engine/src/calibrate.rs` — the module doc's "until then `Calibration::parse` refuses it" corrected (doc only).
- `docs/agent/running.md` § Calibrating (Embedding) and `docs/agent/testing.md` (the `calibration` row).
