# M0-D19 — the web scope red on linux-pc: Node 18 outside an interactive shell, and a null first adapter

Box: run from win-laptop (Laser2025-20), every linux-pc command one non-interactive `ssh -o BatchMode=yes
ybelanger@laserax-ai '…'` call (the block's Box line). Model: claude-opus-5-5, level high (`rung_record.py now`:
`model=claude-opus-5-5 level=high plugin=installed`, the heading's rung). No window was opened on either box.

## Cause (b), measured — logs/M0-D19.probe.log (laserax-ai, Chrome 155.0.8059.39 headless, §6.2.3's Linux flags)
A diagnostic script outside the repo (playwright-core from web/node_modules; a private http.server on 47899 over
web/dist; a 404 page as the origin so index.html's own request does not run) called `navigator.gpu.requestAdapter`:
- The **first request a freshly launched Chrome makes** answers `null` after 270–480 ms, with the console warning "A
  valid external Instance reference no longer exists", whatever the options (`high-performance`, none, `low-power`):
  6 of 6 launches.
- Every later request gets the adapter (`vendor=nvidia architecture=turing`, fallback false) in 2–70 ms: a second call
  on the same page, a first call on a second page, on a page in a new browser context, after a reload (6 of 6).
- A first request made 500, 1000, 1500, 2000 or 3000 ms after the page loads gets the adapter (5 of 5).
- chrome://gpu: GPU process crash count 0, WebGPU "Hardware accelerated but at reduced performance", GPU0 Quadro RTX
  4000 (0x1eb1) *ACTIVE*, GPU1 Intel (0xa780), GPU2 RTX 5090 (0x2b85), Optimus true, gpu_compositing disabled.
So it is a start-up race inside Chrome, once per browser launch, not a crash and not the smoke's probe holding the
adapter (the block's first suspect: the probe runs *after* the page decided). index.html's check was that first
request. A player who starts Chrome on our URL meets the same race; a looser smoke would hide it, so the fix is in the
page.

  and a missing `navigator.gpu` skip both. My reading of §3.5 ("awaits requestAdapter …; when either is missing … shows

- `tests/plants/web-no-gpu-check.patch` — rebased onto the new check's five lines (the same plant: `let adapter = true;`);
  the red-arm's first run showed it no longer applied.
