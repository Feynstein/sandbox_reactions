## Design — the FFT size lives on the GPU (M0-T21's and M0-T30's flags)
The box's padded size is written by `box_fit` on the GPU and never read back, so the kernel's transform is held for
**every** padded size the world's boxes can take: 32 … padded(width) × 32 … padded(height) — 7 × 6 = 42 sizes at
600 × 400. K is real and even on both axes, so K̂ is real and even: each size keeps (nx/2 + 1) × (ny/2 + 1) f32 —
2,067,546 values, **8.3 MB** at 600 × 400 (whole complex spectra: 65 MB). Made once per `Step` on the CPU in f64 with
the twin's `FftPlan` (rows j ≤ ny/2, then columns kx ≤ nx/2: about a quarter of the full 2D work), from the twin's
own `sr_physics::reference::grav::kernel` — so a plant on the twin's kernel reaches the shader too. `grav_columns`
reads K̂(kx, ky) at (min(kx, nx − kx), min(ky, ny − ky)) from the size the box names (an offsets table).

Every P2 dispatch is a fixed size (rows: world height; columns: padded(world width)) with an early return past the box,
or the box's own tiles — the only indirect buffers the latch accepts (latch.rs). Work buffer: world height × padded
width × 8 B (6.5 MB at 600 × 400); g: two f32 planes (1.9 MB). φ and g outside the box keep their last values.

## Findings, not acted on
- §2.8 allows worlds to 2048 cells per axis; gravity's FFT stops at 2048 points, so a box over 1024 cells on an axis
  cannot be solved — P2 refuses any world over 1024 on an axis (exit 4). The default 600 × 400 is inside. For the V
  and the lead (contract-vs-code on §1.3.3 and §2.8), not a code defect.
- The kernel table is made on the CPU at every `Step` build with gravity (42 sizes at 600 × 400, f64): its wall time
  was not measured separately (headless's whole run includes it).
