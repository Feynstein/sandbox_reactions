# M0-D14 — NVIDIA adapters drop out of wgpu's list after ten instances

Box: linux-pc (laserax-ai), 2026-10-09. Model: claude-opus-5-5, level high (rung_record).

## Cause (measured)
- Every `Gpu::new_headless` and the test's `live_adapters` made a fresh `wgpu::Instance` and dropped it. The Vulkan
  loader (1.3.275) dlopens the ICDs at instance creation and unloads them when the instance is destroyed.
- `VK_LOADER_DEBUG=error,warn,driver` on the 11th instance in one process:
  `ERROR: /lib/x86_64-linux-gnu/libnvidia-tls.so.595.99.02: cannot allocate memory in static TLS block` →
  `loader_icd_scan: Failed loading library associated with ICD JSON libGLX_nvidia.so.0. Ignoring this JSON`. Each
  reload of the NVIDIA ICD keeps a piece of glibc's static TLS surplus; once it is spent the ICD never loads again in
  that process, and wgpu lists only the Intel iGPU and llvmpipe — no error reaches the caller.
- Scratch probe (a binary calling the same sr-engine API in a loop, kept in the session scratchpad, not in the tree):
  | mode | result |
  |---|---|
  | create + drop an instance, list | 10 × four adapters, then 30 × [Intel, llvmpipe] |
  | `Gpu::new_headless("quadro")`, dropped | 10 ok, 11th: no adapter contains "quadro" |
  | `Gpu::new_headless("5090")`, dropped | 10 ok, 11th fails the same way |
  | `Gpu::new_headless("quadro")`, every Gpu kept alive | 40 / 40 ok |
  | instance loop with `GLIBC_TUNABLES=glibc.rtld.optional_static_tls=65536` | 40 / 40 four adapters |
- Each failing test passes alone in a fresh process; in the scope the 11th instance falls inside
  `live_one_device_per_adapter_…` (after the Quadro's device), and the next test inherits the dead ICD.
- Not explained: M0-V1 read 10/10 GO the same day on the same driver (595.99.02, installed 2026-10-08 07:52), glibc
  2.39-0ubuntu8.9, loader 1.3.275, the same implicit layers and the same test source. No package changed in between.
  Reading (not measured): whether the ICD really unloads at dlclose depends on timing (the driver's own threads), so
  the ceiling was always there and V1 got past it by luck.

## Fix
- crates/sr-engine/src/gpu.rs: `headless_instance()` — one process-wide `wgpu::Instance` (a `OnceLock`, cloned out),
  used by `Gpu::new_headless`; on wasm (an instance is not `Sync` there) each call still makes its own.
- crates/sr-engine/tests/gpu/main.rs: `live_adapters` lists through `headless_instance()`.
- No expectation loosened; no test case changed.

## Runs (linux-pc)
- Repro before the fix: `bash tests/gpu.sh adapter` 8 passed / 2 failed (logs/M0-D14.log).
- `verify.py adapter --task M0-D14`: GO, 10/0/0 (logs/M0-D14.adapter.log).
- `verify.py --redarm adapter --task M0-D14`: GO — clean GO, plant adapter-case RED (5 failed).
- Claim: see the plan's handoff.
