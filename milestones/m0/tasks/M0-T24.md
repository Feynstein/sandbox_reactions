## Defaults taken (cheap to reverse, declared)
1. **Latency-safe owed.** `plan_frame` takes N·Δt_est off owed when it plans; `on_report` gives that back and takes
   the advanced sim time — over time exactly §1.8.3's `owed −= advanced`, but frames in flight (≤ 2 late) are never
   planned twice. Reports must arrive once per frame with steps > 0, in order (a 0-step report books nothing).
2. **Upper bound on owed: one frame's sim time (rung / f_target).** §1.8.3 states only the lower bound; without an
   upper one the cap's shortfall piles up and is repaid later at another rung (the block's adversarial line). What
   the cap leaves unrun is shown by `running ×`, never repaid. A latch-fired report clamps owed to ≤ 0.
3. **N_max = 1 until a cost is read back** (no c_step yet, or timing off). Safe against a huge N on the first frames;
   the app must turn timing on (`Step::set_timing`) or feed its own `step_ms` — the wasm32 build without
   timestamp-query has cost None (M0-T23), so the web glue needs a wall-clock `step_ms` (flagged to M0-T84).
4. **The empty world** (Δt_next = f32::MAX, M0-T21): no estimate; one step a frame while anything is owed; a report
   whose `advanced` is not finite or ≥ f32::MAX resets owed to 0 and is kept out of `{actual}`. The engine's own
   `sim_time` still sums those Δt (not this block's file; flagged to M0-T84).
5. **Binding** = N_max < ⌈owed/Δt_est⌉ for the cap; the switch reads need60 = ⌈(TOP/60)/Δt_est⌉ against N_max at 60
   (binds when need60 > N_max60, quiet when 2·need60 < N_max60), so the same test holds at 30 and 60 fps.
6. **A rung change** (player or slow-down) clears the cap, `{actual}` and switch windows and sets f_target 60; the
   c_step window is kept (cost per step is the physics', not the rung's). Paused frames record nothing.
7. **`{actual}`** = Σ advanced of the last 60 reports ÷ Σ wall_s of the last 60 running plans.
8. **Banner** clears only when the rung actually changes; `slower` at ×0.1 keeps the core-collapse banner.
9. **Speeds are not thousands-grouped** ("×1000", TOP "×4200"), following §4.12's "ladder rungs as written".
