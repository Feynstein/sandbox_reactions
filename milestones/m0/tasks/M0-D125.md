# M0-D125 — tools_selftest red inside the server's complete loop: a hung case's SIGINT ignored under `nohup … &`

Boxes: linux-pc (laserax-ai) and laserax-ai-server (RTX 4090), 2026-10-31. Model and level: `rung_record.py now` →
model=claude-opus-5-5 level=high.

## Cause, measured
- The three reds (M0-V12's two `--all`, its sweep's `--redarm tools_selftest` clean arm) all ran under `nohup … &` on the
  server (tasks/M0-V12.md, reports/v12.md § The sweep); every pass (M0-V12-ts to ts4) ran in the foreground.
- A shell with no job control starts an async job with SIGINT and SIGQUIT ignored (`bash -c 'grep SigIgn /proc/self/status &
  wait'` → `0000000000000006`; foreground `…0000`), every descendant inherits the ignore, and Python keeps an inherited ignore.
- verify.py's `stop_tree` sends SIGINT, waits 15 s, then SIGKILL. With SIGINT ignored, the plant's `emit.py sleep 20` (timeout
  0.2 s) lived to the SIGKILL: 0.2 + 15 = **15.20 s**, the inner run's time in both server logs, over the plant's `< 10 s`.
- Reproduced on linux-pc (logs/M0-D125.probe.log): `verify.py selftest` foreground GO 358/0, 10.7 s; the same as a
  `bash -c '… & wait'` job NO-GO 1, «PLANT a command that hangs», inner run 15.20 s, 25.7 s — 1 of 1.
- The block's suspect, the log path losing its directory (`/T9.<scope>.log`, `T9.<scope>.log`), is not a cause: the plant's
  detail is `red()`'s `out[-400:]`, which cut a line of the inner run's output at a varying place.
- Not M0-D108's change: `arms_at_once` only caps the arms; the fault predates it and shows whenever the run is an async job.

## Fix (the lead: «Fix verify.py (Recommended)») — toolkit local divergence item 11
- `live_sigint()` after `stop_tree`, called first in `main()`: on POSIX, SIGINT arriving ignored is put back to Python's own
  handler, which exec resets to default, so every case starts with SIGINT live. Real effect beyond the selftest: a timed-out
  case under a backgrounded loop got no SIGINT teardown and cost 15 s; now it stops as in the foreground.
- Side effect, named: a backgrounded verify.py itself stops on SIGINT, as a foreground one always did.
- Selftest: check « a run handed SIGINT ignored still stops a hung command at its SIGINT, not 15 s on (M0-D125) » (the selftest
  sets SIGINT ignored around one inner run, so the check is red in a foreground run too); verify.json plant
  `tools-selftest-sigint` (tests/plants/tools-selftest-sigint.patch: the call dropped from `main()`).
