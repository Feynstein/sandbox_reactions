# M0-D16 — tools_selftest[capture_web]'s two review_page.py cases on win-laptop

Box: win-laptop (Laser2025-20), py 3.12.10, 2026-10-10. Model and level: model=claude-opus-5-5 level=high
(rung_record.py now, plugin=installed). Log: milestones/m0/logs/M0-D16.log (+ M0-D16.tools_selftest.log,
M0-D16.tools_selftest.redarm.log, M0-D16-inj.tools_selftest.log for the injected-bug run).

## Cause (measured)
- Not the killed processes: no python/node left running (only the lead's Chrome), and the case alone on a quiet
  box reproduced it — `verify.py tools_selftest --case capture_web` NO-GO, the same two failures.
- Not a native crash: capture_web.mjs's consumer check spawns `process.env.PB_PYTHON || 'python'` on win32 and the
  harness never set PB_PYTHON. From Node, bare `python` is `C:\Program Files\Python314\python.exe` — Python 3.14.8,
  installed machine-wide 2026-10-09 (InstallDate 20261009, folder 16:50, two hours before M0-D13b's run) with only
  the « Core Interpreter », « Executables » and « Add to Path » components: `Lib\` holds only site-packages, no
  stdlib. Its startup dies « Fatal Python error: Failed to import encodings module », and the fatal-error dump ends
  « Current thread … <no Python frame> » — the selftest's tail kept only those last lines. Exit 1, from any cwd.
- The machine PATH (Python314, Python314\Scripts) comes before the user PATH (Python312), so `python` and `where
  python` both reach 3.14 first; `py -0p` lists 3.14 as the default (`*`), so `py` and `py -3` die the same way.
  `py -3.12` (the toolkit's call, Hazards) is unaffected.

## Fix (tools/pb/verify.py, 3 lines of code + a check and a plant)
- `case_env`: `env.setdefault("PB_PYTHON", sys.executable)` — every case, Python or not, gets the harness's own
  interpreter; a caller's value still wins. capture_web.mjs already reads PB_PYTHON; no change there.
- selftest: fake kind `pbpy` (GO when PB_PYTHON resolves to the child's own interpreter); a check that a case gets
  it, and a PLANT (case_env without PB_PYTHON) that must read red; PB_PYTHON popped/saved like PYTHONFAULTHANDLER.
  verify selftest 169 → 171 checks, plants 100/100 → 101/101 red.
- Nothing loosened: review_page.py's two checks are unchanged and now run on 3.12.10, where they pass.

## Runs (all on win-laptop)
- repro before the fix: `tools_selftest --case capture_web` FAIL (0/1, 2 failures).
- after: `--case verify` PASS (171/0, plants 101/101); `--case capture_web` PASS (85/0).
- injected bug (the setdefault line removed): `--case verify` FAIL on the new check; `--case capture_web` FAIL, the
