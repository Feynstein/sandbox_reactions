## Findings (not acted on)
1. The linearisation's ∇ω holds the gate fixed (X_j := 1, Y_e Σ held), so N_Fe's sub-step overshoots the gate's own
   closure: iron 1 % over Σ_N, one 10⁴ t.u. sub-step (burn_dx-limited) moves 9.09 % of the iron where the gate shuts at
   0.99 %. The twin does the same (contract's linearisation); bounded by burn_dx, never negative. For M0-V6 to weigh.
2. A flag set during bare steps (`Step::run`, no frame) stays set in the latch record until a frame's controller takes it,
   so the first frame after bare steps can fire on a stale flag. Not new (the hook behaves alike); headless's bare runs
   are unaffected (no controller).
3. After the frame's stop the P6 dispatches are zeroed with the rest (the `react_latch` slot is the latch's [1,1,1] one).
4. The sinks' P3 will set the same flag word with its own atomicOr (M0-T52+): no change needed here.
5. Cost: not re-measured. One more one-invocation dispatch per step with P6 on; `react_cells` now carries the eps_nu power
   (≤ 8 multiplies) per sub-step. The hot-core figure of M0-T46 (42.4 ms on the Quadro) is M0-V6's.
6. Over the ceilings: 8 code files (react.wgsl, react.rs, latch.rs, mod.rs, headless.rs, timing.rs, burn.rs, neutrino.rs)
   + verify.json + 3 plants; ≈ 540 new lines. Sizing miss: `ReactSetup`'s two fields rippled into three call sites.
