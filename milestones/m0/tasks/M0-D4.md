# M0-D4 — plan.py's selftest fails one check on Windows (2026-10-08, win-laptop)

## Cause (measured — neither suspect in the block)
The `Read:`-over-500-lines check writes the fixture's **native absolute path** into the fixture plan's `Read:` line
(`big = os.path.join(root, "big_reference.md")`) and expects that same string back in the lint's WARN. The lint
tokenises `Read:` with `PATH_RE = [\w./-]*\w\.[A-Za-z]{1,5}`, which holds no `\` or `:`; on Windows
`C:\Users\…\big_reference.md` therefore yields the token `big_reference.md`. `file_lines` still finds it (it sits
beside the fixture plan, a folder the lint searches), so the WARN fires correctly — it just names the basename, and
the check's substring match on the full path misses. On linux-pc `/tmp/…/big_reference.md` matches `PATH_RE` whole.
- Not the exact-comparison suspect: the check is a substring test (`… in out`); the extra «3 open block(s) carry no
  rating» WARN is just more of `out`, printed on every box.
- Not the lock-retry suspect: the first repro run printed no «needed 2 attempts» line and still failed.

## Fix (selftest only — the lint's behaviour unchanged), one hunk
`bigname = os.path.basename(big)`; the two `Read:` fixtures and the expected WARN use `bigname`. Real plans name
repo-relative forward-slash paths, which is what the check now exercises. The lead's answers (question tool,
2026-10-08): landing «Both, identical»; shape «Selftest only» (not widening `PATH_RE` to Windows paths).

Where it landed: `tools/pb/plan.py` and PLAYBOOK.md annex §A's `#### tools/pb/plan.py` block, byte-identical (LF,
compared as bytes: identical); the `<!-- pb:file ... md5: -->` marker `4886df610160` → `9c293922e286`. No other
file carried the old md5.
