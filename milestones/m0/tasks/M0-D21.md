# M0-D21 — sim time as a function of the steps run

Box: win-laptop (Laser2025-20), NVIDIA GeForce RTX 4080 Laptop GPU, Vulkan. Ran on `model=claude-opus-5-5 level=high`
(rung_record.py now; the heading's rung, no mismatch).

## What exists now
- **The clock** (crates/sr-engine/shaders/reduce.wgsl): `DtState` gains `time_lo`, `time_hi` — the sim time as an f64's
  bits. P1's `dt_advance` adds the step's Δt to it with `clock_add`, an exact f64 add on u32 words (significands at bits
  62..10, guard + sticky below, round to nearest, ties to even) — the CPU's `t += f64::from(dt)` bit for bit, in step
  order. A Δt of 0 or ≥ the largest f32 (an empty box, M0-T21) adds nothing. A step the latch stopped runs no P1 (its
  slot is zeroed), so it adds nothing either. Frames, their grouping and bare steps all give one value per step count.
- **Readers** (crates/sr-engine/src/step/dt.rs, latch.rs): the record is 10 words (`dt::RECORD_WORDS`, shared with
  latch.rs's `DT_WORDS`); `DtReport.sim_time` (new field), `FrameReport.sim_time` (from the frame's readback, no CPU
  accumulator any more — `Readbacks.sim_time` removed), `resume_records` (→ `dump_state`'s header) and `restore` (←
  `load_dump`, the clock written back exactly) all read or write the clock. `FrameReport.advanced` unchanged (the frame's
  own f32 sum, time control's).
- **Headless** (crates/sr-engine/src/headless.rs): summary.json's `sim_time` and the DONE line read `read_dt().sim_time`
  after the run — the value the final dump writes.
- **Tests**: tests/gpu/dump.rs + 3 cases (8 now): 40 steps of the cold start as 1 × 40, 2 × 20, 40 × 1 frames and bare →
  four byte-identical dumps, each report's sim time the dump's, 0.000e0 off the f64 sum (bound 1e-9; the f32 running sum
  3.599e-7 off — the control arm); an empty world (Σ = 0) → Δt = f32::MAX, 10 bare steps then a 10-step frame, sim time
  0; `headless --scene preset:sun --world 256x256 --steps 100 --out` → summary 3.02641075104475021 = final dump = an
  in-process twin stepped one bare step at a time (its planes = the dump's, bit for bit), 0.000e0 off. The summary's
  value is parsed from its own token (serde_json reads floats best-effort, as dump.rs knows).
- Plant `dump-sim-time-skip` (tests/plants/dump-sim-time-skip.patch): P1 never adds — V3's symptom (a). Red: 3 failed.

## Deviations (declared)
- **The grading checks changed**: (1) tests/gpu/latch.rs's `poll` case asserted `FrameReport.sim_time` = the f64 sum of
  the frames' f32 `advanced` — the defect itself; it now asserts the per-step f64 sum, bit for bit (stricter than the
  1e-9 bound); the case count stays 5. (2) tools/pb/verify.json's `dump` scope: `expected` 5 → 8, the plant added, the
  desc extended. Both scopes red-armed (`--redarm dump`: 2 plants red; `--redarm latch`: `latch-off` red).
- **Files**: 6 code files (the ceiling) + verify.json + the plant + docs/agent/architecture.md and testing.md rows. To
  stay at 6, latch.wgsl's read-only copy of `DtState` keeps 8 fields (it reads the first words of a 10-word buffer —
  valid) and dump.rs's doc line « the frames' sim time » (on `dump_state`) is left stale.

## Measured, not acted on
- An empty world's frame reports `advanced: inf` (ten f32::MAX summed in f32; dump log, `an_empty_worlds_steps…`).
  Not filed: the Deliver keeps `advanced` the frame's own, and time control's empty-world handling is M0-T24's
  (`time_control` scope: « the empty world's Δt survived »). If time control ever books `advanced` as owed time without
