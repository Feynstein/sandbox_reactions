# M0-D162 — `--measure-ui` read t_eff_sun_sb one ULP off: the calibration's parse reads every number as written

Ran on linux-pc (laserax-ai), 2026-11-09; the claim on laserax-ai-server, RTX 4090 (R18). Rung line: `model=claude-opus-5-5 level=high`
(the heading's Opus 5.5, high — no MISMATCH).

## The cause, measured
- serde_json 1.0.151 without `float_roundtrip` reads a decimal best-effort. A scratch probe (serde_json =1.0.151, the build's own
  features) parsed all 43 tracked JSON files of the tree and wrote each back; Python (correctly rounded) compared every float:
  259 literals come back as a neighbouring double. In the files the game reads: assets/calibration.json `t_eff_sun_sb`
  11.544176535966779 → 11.54417653596678 (the filed symptom), assets/reactions.json `records[1].q_ratio` 0.09259259259259259 →
  0.0925925925925926, scenes/cold_co_disk.json 256 `objects[*].sigma` and `overrides.k1e` 127.80000000000001 → 127.8; the rest are
  logs (rung records' `client_usd`).
- The writer was never at fault: `to_string_pretty` prints the shortest round-trip form of the double it is handed.

## Why not the Deliver's first idea (serde_json's `float_roundtrip`)
- A Cargo feature unifies across the build: every serde_json parse would change, `physics_hash_of` among them. The hash is the SHA-256
  of the canonical text of the *parsed* assets, and reactions.json's q_ratio reads one ULP apart under the feature — the physics hash
  moves, assets/calibration.json (`a480dc19a54e…`, M0-V14's) is refused with exit 6 everywhere (G-CAL), and every physics run's
  reactions constant and cold_co_disk's scene input move by an ULP. That is a recalibration, not a parse fix — out of this block.
- §1.2's features unchanged ([M0-D76]'s choice too); no new crate, no ask needed.

## What exists now
- crates/sr-physics/src/calibration.rs: `Calibration::parse` calls `read_as_written(&mut root, text)` right after serde_json's parse —
  every number literal outside strings is re-read by `str::parse::<f64>` (correctly rounded), keyed by what serde_json made of the
  same literal (`from_str::<Value>(literal).as_f64()`, the very path the tree took), and each float of the tree takes its literal's
  value; two literals serde_json reads as one double but naming two are refused (`<json>`, "two numbers read as one double") —
  never seen, refused rather than guessed. Only the calibration's parse changes: physics_hash, the registry and scenes still read
  as before (their values and the hash unchanged).
- crates/sr-engine/tests/gpu/calibration.rs: `every_number_of_the_calibration_is_read_back_as_written` — assets/calibration.json
  parsed, t_eff_sun_sb bit for bit, `to_json()` equal to the file byte for byte; 2,000 doubles over 1e-10…1e10 (an LCG, fixed seed)
  written in their shortest form, read back bit for bit at `t_eff_sun_sb` and inside a `stage_durations_sb` pair; the case asserts
  plain serde_json misreads at least one of the sweep, so it keeps reaching the fault.
- tests/plants/calibration-lossy-parse.patch (the `read_as_written` call removed); tools/pb/verify.json `calibration`: expected 12 → 13,
  the plant and its path, the desc's [M0-D162] clause; docs/agent/testing.md's row (13, the plant).
