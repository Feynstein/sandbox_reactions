# M0-D2 — rung_record.py's selftest fails 4 checks on Windows (2026-10-08, win-laptop)

## Cause (measured)
`cmd_now` prints this host's install line — `plugin_report(os.getcwd(), windows())`, a PowerShell line on
Windows (`; & "<client>" ...`), a POSIX line elsewhere (`&& "<client>" ...`) — as §A.9 specifies. The selftest's
expected line (`posix = lambda c, exe=LINUX_EXE, verb="install": 'install: node ... && ...'`) was always the POSIX
form, so on Windows the four checks comparing `now`'s printed line against it (missing, another project's scope,
stale, no `$CLAUDE_CODE_EXECPATH`) were red. The tool's behaviour was right; the fixture assumed a POSIX host. The
suspected causes (a POSIX home, `installed_plugins.json` paths) were not involved: the `here` / `other` scope reads
were already correct on Windows.

## Fix (selftest only — the tool's behaviour unchanged)
`posix` → `host`: the expected line is the PowerShell form when `windows()`, the POSIX form otherwise, both
hand-written (never built by `install_line`, so the plants on `install_line` still bite). One check renamed:
«now: missing → this host's line (POSIX; PowerShell on Windows): ...». On linux-pc `windows()` is False and the
expected string is byte-identical to before.

Where it landed — the lead's answer (question tool, 2026-10-08): «Both, identical». `tools/pb/rung_record.py` and
PLAYBOOK.md annex §A.9's `#### tools/pb/rung_record.py` block, byte-identical (compared LF-normalised: identical);
the annex's `<!-- pb:file ... md5: -->` marker updated `b4afcebce9b1` → `3a3c3a3ae9b2` (md5 of the file, first 12
hex — the old value reproduced from `git show HEAD:tools/pb/rung_record.py`). No other file carries the old md5.
