### What changed
- `crates/sr-app/src/status.rs`: `pub const FALLBACK = 47811..=47830`. `serve(port)` tries `port` first. On any bind error it
  binds the first free port of FALLBACK (skipping `port`). If none is free, it returns `port`'s own error. It now returns
  `(Arc<Status>, u16)`, the port it listens on. The unit test asserts the bound port. A unit test that binds the range was
  written and then removed: it would race the desktop scope's 47811 when both run in parallel.
- `crates/sr-app/src/desktop.rs`: prints `SR-STATUS-PORT <n>` only when n differs from `--status-port`. The error line is now
  `SR-ERROR --status-port <p>: cannot listen on 127.0.0.1, nor on 47811–47830 (<os error>)`, with the same exit (EXIT_ARGS).
- `tests/smoke.sh`: case `port-taken`. Under the port lock, a Python listener holds 47811 for the whole case. The game starts
  straight. On linux-pc that is `env -u WAYLAND_DISPLAY -u WAYLAND_SOCKET -u XDG_SESSION_TYPE setsid xvfb-run -a … --adapter
  llvmpipe`, so the whole process group is killed. On win-laptop it is `--offscreen-window`. A poller reads `SR-STATUS-PORT`,
  then polls /status until "ready" (90 s). The port must be in 47812–47830, and it must be bindable again after the stop.
