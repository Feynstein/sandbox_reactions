# M0-D179 — a long command says its start and a heartbeat with its ETA

Box: linux-pc (laserax-ai), 2026-11-15. Model and level: `rung_record.py now` → model=claude-opus-5-5 level=high. Filed and
built in M0-D178's session on the lead's word: «can you also make sure that verify.py shows some progress and and ETA. right
now the endings run is running and its not printing anything».

## Cause
Two design choices left a long single command silent until its verdict (`endings` ≈ 45 min, one `cargo test`):
- M0-D27's and M0-D65's live lines (`>> … started`, the ETA line) are said only by a run of several steps.
- A command's own line (`.. <label> <s>s`) is said only when the command ends.

## What changed (tools/pb/verify.py; toolkit_local_diff.md item 13)
These lines appear on a terminal only (stderr a tty, no `--no-progress`), on stderr, display only:
- **A one-step run says its start:** `>> endings · started · ≈ 45m10s by this box's last run`, or `no past run on this box to
  time it by`.
- **A red-arm's lone arm says its start:** `>> endings · plant fate-swap · started`.
- **A command still running says a heartbeat every `PB_HEARTBEAT_S` seconds (default 60):**
  `.. endings · running 12m00s · 2 of 9 cases done · now endings::<case> · ≈ 42m00s left by its pace (2 of 9 in 12m00s)`.
  - Before a case has ended, the ETA comes from this box's last run of the scope: `≈ … left by this box's last run (…)`, or
    `over this box's last run (…) by …`.
  - Cases are counted from libtest's lines in the output streamed to the part file. `test <name> ... ` marks a start, and
    `ok|FAILED|ignored` marks an end, either on the same line or on a line of its own after the test's output. The second
    form is what `--nocapture` produces, and it's how tests/gpu.sh runs.
  - Checked on M0-T104's bh, giant and mass_up logs: started = ended (2/2, 1/1, 2/2).

Unchanged: the counts line, the verdict, the logs, the record and the anchor. Nothing is said on a pipe or with
`--no-progress`.

## Named
- An arm's ETA reads the scope's last plain run, not the red-arm campaign's. On `ending` that was the cached 0.11 s, hence
  «over … by». On `endings` the scope run (≈ 45 min) is the right yardstick for a plant arm.
- The lead's `endings` run already running when this was asked cannot gain the lines. The next run started with this
  verify.py will have them. On laserax-ai-server that needs this tree synced there (R18).
