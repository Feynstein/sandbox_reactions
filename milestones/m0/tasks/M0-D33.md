# M0-D33 — A dump carries F

Box: `linux-pc` (laserax-ai; physics on the RTX 5090, R12). Model: claude-opus-5-5, level high (`rung_record.py now`:
`model=claude-opus-5-5 level=high plugin=installed`, matching the heading).

## What exists now
- **The format** (`crates/sr-engine/src/dump.rs`): `Dump` gains `flux: Option<Vec<f32>>`, F's two planes (`side.flux`:
  F_x, then F_y, row-major). When it is `Some`, `to_bytes` writes them after §2.2's 14 channels. The header's `resume` gains
  `"flux": true|false`, which is always written and required on read. Version stays 1.
- **Refusals** (`from_bytes`): a missing `flux` key, or one that is not a boolean, is refused. So is a body the flag
  disagrees with, and the message names the flag: `header.resume.flux: true, but no F planes follow §2.2's 14` or
  `header.resume.flux: false, but F's 2 planes follow §2.2's 14`. Any other length is still `truncated …` or `… bytes past
  the last plane`.
- **dump_state / load_dump**: their signatures are unchanged. `Step::side_flux()` (step/heat.rs) returns the step's
  `side.flux` when it runs P5, because `Heat` now keeps a handle on that buffer. `dump_state` reads F back.
  `load_dump` writes F into `side.flux` and refuses two mismatches, both before it writes anything:
  - F into a step without P5: «dump holds F, and this step runs no P5 to keep it (heat off)»
  - a dump without F into a step with P5: «… its first step would push with F = 0»
- **headless.rs**: only `twin_dump` (`flux: None`; the twin runs no P5, M0-T48). `--load-dump` needed no change because it
  goes through `load_dump`.
- **Tests** (`tests/gpu/dump.rs`): 8 cases, the same count, with assertions added to existing cases:
  - The header's `resume.flux` is false for a run without P5.
  - The headless resume's s_100.bin is read by hand: the flag is true, the file is 16 planes long, and F is non-zero
    (8,836 cells per plane). This proves the byte-for-byte resume can see a lost F.
  - Both `load_dump` refusals.
  - The final dump's F equals `side.flux` of the in-process run, bit for bit.
  - A dump with F reads back the same, and the flag's three refusals and a cut F plane are refused.
- **Plant** `tests/plants/dump-flux-zero.patch`: `load_dump` uploads zeros into F. It is registered in verify.json's `dump`
  plants, and the scope's `desc` has gained the F clause.
- **Contract** §0.5 [M0-D33]. The plan's Superseded section has its mirror line (written with the file-edit tool, because
  plan.py has no call for that section).

## Deviations
- **Files**: the block's `Files:` line (marked unverified) named headless.rs for `--load-dump`, but that path needed
  nothing. The F buffer is reached through `Step::side_flux()` in step/heat.rs, a file the line did not list. In total: 4
  code files (dump.rs, step/heat.rs, headless.rs, tests/gpu/dump.rs), plus the plant and verify.json. About 130 new lines.
- **Defaults taken** (cheap to reverse): `flux` is required, with `false` written when there is no P5, rather than
  optional. This matches the header's existing rule that a missing key is refused. Both `load_dump` mismatches are
  refusals rather than silent zeroing or dropping, because a resume across a changed heat switch cannot be bit-identical
  anyway.
