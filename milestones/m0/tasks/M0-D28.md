# M0-D28 — the web scope's `ready` smoked a server another scope stopped

Box: linux-pc (laserax-ai), 2026-10-13. Ran on Claude Code, Opus 5.5, high (`rung_record.py now`: model=claude-opus-5-5 level=high).
Probes and runs: logs/M0-D28.log (all of them, in order).

## Cause (measured), not the one the block suspected
- **The block's guess is wrong.** `launch.py start web` never adopts a server: with a foreign server on 47812 it refuses («port 47812
  held by a process we did not start - not reusing», probe 2), and a second start reads «already running as pid … - not restarting»
  (probe 3). `launch.py stop` returns only once the port refuses (probe 1: refused 0.1 ms after stop). `verify.py` stops nothing
  between cases (probe 4).
- **launch.py's records are the box's, not the task's.** `--task` names only the log file: `launch.py stop --task A` stopped a web
  server started under task `A-web`, and under the unrelated task `ZZZ-p6b` (probe 6). So a bare `launch.py stop` (no service name)
  stops every service on the box, whatever scope started it. `stop <service>` stops that service alone (probe 5). `status` takes no
  service and always lists all five.
- **Who stopped web in M0-T34's claim run:** the desktop scope's `launcher` case (08:54:46, 6.84 s, so it ended in [52.84, 53.84))
  ends on two bare stops, start.sh's last line `launch.py stop --task launcher` and then tests/smoke.sh:54. `web[ready]` launched its
  own server at 08:54:53 (the only entry in logs/M0-T34.launch.web.log), read it ready in 0.1 s, and was refused at [53.74, 54.74).
  The launcher's port lock (47811) and web's (47812) are different files, so nothing kept the two apart. The first claim run (08:51)
  missed it by timing.
- **The other direction too:** web's own exit trap was a bare `launch.py stop --task "$task"`, so a web case ending mid-smoke of
  `desktop[window]` could stop its game. And the launcher case's check `running: 0` over all services would read a live web server
  as a leftover.

## Fix (the lead, 2026-10-13: «Launchers stop their own (Recommended)», «One named exception (Recommended)»)
- start.sh, start.bat, start.ps1: `launch.py stop <the service they started> --task launcher`. Contract §0.5 [M0-D28] overrides §3.6's
  « `launch.py stop` », mirrored in the plan's Superseded section.
- tests/smoke.sh, the launcher case: stops `$service` only, reads its own `<service> stopped` status line, and runs beside a
  **decoy web server**, started under the web scope's port lock (flock fd 9, or the `.d` mkdir lock), which must still be running
  after the launcher. That is the forced overlap, kept as the regression check. It is stopped and the lock freed on every exit path.
- tests/web/check.sh: the exit trap stops `web` alone.
- Plants: `launcher-stop-all` (new: start.sh back to the bare stop; desktop[launcher] reds «the launcher stopped a service it did not
  start»), and `launcher-no-stop`'s removed lines refreshed to the new stop lines.
- Files: 9, three over the ceiling (named exception; start.ps1 and the old plant's context came with the same line change).
