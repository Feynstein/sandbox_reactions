## Readings declared (cheap to reverse; the contract's §2.12.5 does not say)
- A state trigger (`object_until`, `mass_until`) reads the heaviest object, so it waits for the first object the observers have found: the first read is after step 1. A `mass_until` with no object does not fire (neither bound).
- While a state trigger is unspent the run takes one-step chunks (a summary and a `Watch::update` per step), so that no read lags the step it is made at. This is the run's cost for the property; a `--until` run with such a trigger frames per step, like `calibrate`'s one-step stretches (M0-D80).
- `{"step": n}` holds from step n on (≥), applied once; the chunk ends at n. Step n is the (n+1)th step; a file with step triggers only runs full chunks between them.
- `frames` (1–8, default 1) = that many applications in the one step (the heat/cool factors compound per frame held, paint adds `frames × paint_sigma`). One firing is one frame's first step (T76's flag: edits land in a frame's first step).
- The queue takes 8 edits a step; the rest wait in the file's order. A repeating `mass_until` adds its copies only when the backlog is empty.
- `mass_until` stops for good once passed (no resume). `object_until` fires once.
