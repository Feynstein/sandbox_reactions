## What changed (tools/pb/verify.py; toolkit_local_diff.md item 12)
- **The record (Deliver 4).** Every whole run of an armed scope writes `fingerprint` (the existing `fingerprint()`: manifest
  entry, the files `paths` match, plant files and their targets, the runner) and `adapter` (`SR_TEST_ADAPTER`, or null) into its
  scope entry in `loop_times.jsonl`. "Whole" means no `--case` and no case vouched by the anchor. The fingerprint is taken
  before and after the run, and a mismatch writes none. A red whole run writes them too, so the same bytes run red void an
  older green. A `--case`, partly vouched or moved-tree run writes no fingerprint and so never stands for the scope.
- **The reader.** `green_proof(name, logs, box, fp, adapter, fresh)` replaces `clean_proof`. The newest record on this box with
  this fingerprint and adapter decides:
  - a whole run GO, or a red-arm whose clean arm *ran* GO, is the proof;
  - a red is none;
  - a `--case` or vouched run, a PROVEN clean (itself a reading), or a record with no `adapter` key (before M0-D178) is read
    past.
- **`--redarm <scope>` (Deliver 1–2), `clean="record"`.** With a proof, it runs the plants only and the line reads
  `<scope> · clean: proven by <task> <ts> (a run of the scope; fingerprint …) - not re-run`. With none, it runs nothing:
  `redarm: refused - nothing run`, NO-GO naming `python3 tools/pb/verify.py <scope> --task <ID>`, or `--with-clean`.
- **`--redarm <scope> --with-clean` (Deliver 3), `clean="fresh"`.** It runs the clean arm, then the plants, whatever record
  stands.
- **Reuse of a clean arm that runs (the lead, mid-task: «make sure if the clean arm is run, other tests re-use it»).** A
  campaign's clean GO is recorded with the fingerprint and adapter, so the next `--redarm`, the sweep or the loop reads it
  (selftest: Q4 → Q5, R6 → R7).
- **The sweep (`--redarm --moved`), `clean="auto"`.** It reads the record when one stands (a `--all` run, a scope run, an
  earlier clean arm), else runs the clean arm as today. Why not refuse: the sweep is the heavy tier's batch re-proof at V and
  TR blocks. Its `--all` runs right before it and now writes the record, so the clean arm runs only where no green on these
  bytes exists. Refusing there would just make the V run the scope again by hand.
- **The loop's plants (`--changed` / `--all`, a scope whose entry changed), `clean="auto"`.** `run_scopes` hands the hook the
  run's record before writing it (`hook(rec)`), so the claim red-arms a changed scope off the green run it just made.
